## 本轮兼容性修正

- **传输协议与本地监听分离。** LanDrop 仍广播 HTTP 接收地址，但接受 HTTP／HTTPS 对端；出站注册、传输和取消跟随对端协议，不再直接排除默认 HTTPS 设备。
- **mTLS 身份。** AndroidKeyStore 生成持久 RSA 客户端证书；广播和请求声明证书 DER 的 SHA-256 指纹。连接 HTTPS 对端出示证书，使用发现到的指纹核验服务端证书，不增加加密设置项。未知端点扫描只用于发现，返回 JSON 指纹还必须与握手证书一致。
- **v2.2 发现。** 对不带旧 `announce` 标志的广播仍进行单播注册；只有注册确认后才从该广播发布设备。扫描支持 HTTPS 与 HTTP。
- **目录与元数据。** 发送保留相对路径；私有本地 URI 不进入 JSON；接收防止越界并保留层级。准备请求的元数据上限与普通注册分开，避免继续受 64 KiB 注册上限限制。
- **摘要与结果。** 摘要不匹配返回 422，同一 session/token 可整文件重试，最多三次。传输失败与用户取消分开记录，终止上传失败后请求远端清理剩余目标；不因某一文件成功而把先前失败改成成功。
- **确认与取消。** 接收确认仍为 60 秒，发送读等待调整为 90 秒；待确认时取消会终止本地准备请求并向对端发送无 sessionId 的取消；接收按发送地址匹配待确认取消并使旧确认失效。

首次从旧开发安装升级到证书身份时，网络指纹会变化一次；之后改名和服务重启不更换证书。AndroidKeyStore 的实际签名行为仍须在目标电视/API 21+ 设备验证。HTTP 入站保持明文，不应把 HTTPS 出站能力描述为所有方向均已加密。

## 必须继续验收的核心事项

- 与固定版本原版 Android／桌面客户端双向发现、注册、文件和消息互传，覆盖两种启动顺序、改名和网络切换。
- AndroidKeyStore 自签名证书、TLS 1.2/1.3 客户端证明、身份跨进程重启稳定及不同电视厂商支持。
- SAF／U 盘／MediaStore／旧存储的路径、同名文件、授权撤销及空间不足；空目录当前不传输。
- 已接入 422 摘要失败响应及同 session/token 的整文件重试，最多尝试三次；接收目标在摘要通过前不发布，耗尽后清理并报告失败。相关设备测试已加入，仍需实际执行和原版双机验收。
- 接受／取消同时发生、连接直接断开、重试和部分完成结果；连接断开当前不能代替显式取消，具体差距继续列 P0。
- 在设置或记录页面时，来件可能通过通知／已授权悬浮入口提示；回到主页可处理待确认请求，需按电视系统实际可用入口验收。
